# Адаптация экрана и сохранение регистра

HSM 5.5.2 автоматически адаптирует хинты стандартного рендерера для каждого игрока.
Сначала хинт сдвигается внутрь доступной области; если он больше области, уменьшается
текст вместе с размерами `<size>` и межстрочными интервалами. Переносы строк не добавляются.
Исходные объекты `Hint`, `DynamicHint` и их `AutoContent` не изменяются.

## Установка

Замените существующую DLL HSM сборкой для своего загрузчика и перезапустите сервер.
Не устанавливайте одновременно EXILED- и LabAPI-варианты. Сторонние плагины,
использующие существующий API HSM 5.5, пересобирать не требуется: публичные сигнатуры
и AssemblyVersion 5.5.0.0 сохранены. Новая EXILED-сборка требует EXILED 9.15.3.
Совместимость всех исторических выпусков HSM и сторонних модификаций не подразумевается.

## Настройки

Добавляются в обычный конфиг HSM:

```yaml
enable_screen_adaptation: true
screen_reference_height: 1000
screen_top: 0
screen_padding: 20
preserve_case_by_default: false
```

Это координаты HSM, **не пиксели монитора**. Внутренняя ширина текстового контейнера
2400 единиц не равна видимой ширине экрана. Безопасная область рассчитывается так:

- ширина: `screen_reference_height * aspectRatio`;
- X: от `-ширина / 2 + screen_padding` до `ширина / 2 - screen_padding`;
- Y: от `screen_top + screen_padding` до `screen_top + screen_reference_height - screen_padding`.

Высота 1000 и отступ 20 — консервативная исходная калибровка для HSM, а не измеренные
параметры клиентского canvas. Клиентский canvas отсутствует в серверных reference DLL.
При игровой проверке подберите высоту, верхнюю границу и отступ при необходимости.
Метрики шрифта HSM также приблизительны; нестандартные шрифты, спрайты и rich-text
теги изменения геометрии, которые HSM не измеряет (например `margin`, `indent`, `space`,
`cspace`, `mspace`, `width`, `rotate`), не дают гарантии точного попадания в экран.

Сервер использует числовое соотношение сторон из `ReferenceHub.aspectRatioSync`,
а не точное разрешение. Игра ограничивает переданное значение снизу единицей;
поэтому портретные экраны нельзя точно определить этим API. Начальное значение
компонента также равно 1:1 до получения сообщения клиента. Неизвестные или
некорректные значения отключают адаптацию до появления корректных данных.
Высота должна быть 100–10000, отступ — неотрицательный и меньше половины высоты.

В EXILED смена соотношения сторон обрабатывается через `Player.ChangedRatio`.
Основная корутина дополнительно проверяет значение, включая LabAPI-вариант.
Данные игры читаются на основном потоке; расчёт использует отдельный снимок.
Устаревший результат после смены экрана не отправляется, кэш динамических позиций
сбрасывается. Смена разрешения с тем же соотношением сторон не требует пересчёта.

`DynamicHint` ищет место в пересечении своих ограничений и безопасной области.
При отсутствии места `Hide` скрывает хинт, а `StayInPosition` оставляет его около
целевой позиции, ограничивая экраном. Статические хинты не получают новый алгоритм
устранения взаимных пересечений: их сдвиг может привести к перекрытию.
Пользовательские реализации `IHintParser` сохраняются, но адаптация их произвольного
вывода автоматически не выполняется.

## Сохранение регистра — PR №42

Функция перенесена из [PR №42](https://github.com/MeowServer/HintServiceMeow/pull/42).
Новый `AbstractHint.PreserveCase` по умолчанию равен `false`. Чтобы применить
сохранение регистра ко всем существующим плагинам без изменения их кода, включите
`preserve_case_by_default: true` и перезапустите HSM/сервер.
Эффективное значение — глобальная настройка **или** свойство хинта. Явные теги
регистра и `noparse` сохраняют приоритет. Форматирование выполняется до измерения.

## Проверка

Разработчиком выполняется только сборка EXILED и LabAPI. Проверка на игровом сервере,
калибровка границ и загрузка ваших уже собранных плагинов остаются за владельцем сервера.
